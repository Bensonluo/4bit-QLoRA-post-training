# 主数据匹配项目审查修复计划

## P0 — 必须修（阻塞训练/评测，或导致结果不可信）

### P0-1: 评测错误静默吞掉
- **问题**: `evaluate.py` 第 191 行 `except Exception:` 没有任何日志，API 超时、网络错误、模型输出异常全看不到
- **后果**: 你以为模型预测错了，其实是解析失败或 API 挂了；latency=0ms 的样本全是异常被吞掉的
- **修复**: 加 `logging.exception()` 或 `print(f"ERROR: {e}")`，至少记录错误类型和样本索引
- **文件**: `eval/evaluate.py`
- **工作量**: 5 分钟

### P0-2: 训练没有验证集
- **问题**: `train.py` 只有 train_dataset，没有 eval_dataset，训练完全盲飞
- **后果**: 不知道何时过拟合；可能第 1 轮后就过拟合了，但你还在跑第 2 轮；loss 下降但 eval acc 下降也看不到
- **修复方案 A（快）**: 从 train.json 中分出 10%（600 条）作为 val.json，训练时加载 eval_dataset
- **修复方案 B（更准）**: 每 `save_steps` 步后用当前模型在 val 集上跑一轮评测，保存最佳 checkpoint
- **文件**: `scripts/train.py`, `scripts/generate_data.py`（分数据）
- **工作量**: 30-60 分钟

### P0-3: REFERENCE.md 未同步更新
- **问题**: 文档仍是 4 级（A/B/C/D），实际已改为 3 级（A/B/D）
- **后果**: 你自己过几天也会忘，后续会话或新人按旧文档理解，再次踩坑
- **修复**: 更新等级描述、数据分布、基线结果
- **文件**: `REFERENCE.md`
- **工作量**: 10 分钟

## P1 — 强烈建议修（影响训练质量或评测准确性）

### P1-1: 训练输出目录 vs 评测加载目录不一致
- **问题**: 训练输出到 `outputs/master-data-matching/`，但评测脚本从 `domains/master_data/models/` 硬编码路径加载
- **后果**: 每次训练完要手动复制或改路径，容易搞错版本（评测的是上一轮模型，不是你刚训的）
- **修复**: 评测脚本支持 `--model-path` 参数，默认指向训练输出目录
- **文件**: `eval/evaluate.py`
- **工作量**: 15 分钟

### P1-2: 评测 API 没有重试机制
- **问题**: 并发评测时偶尔有 API 超时或 429 限流，直接丢样本
- **后果**: 200 条评测可能丢 3-5 条，结果有偏差
- **修复**: `call_model()` 内加 `@retry(exceptions=(Timeout, RateLimit), max_attempts=3)`
- **文件**: `eval/evaluate.py`
- **工作量**: 15 分钟

### P1-3: 机构 reasoning 硬编码 / 产品缺少 reasoning
- **问题**: 机构匹配的 reasoning 是随机选的固定字符串（"P1(精确匹配)->判定true"），不是根据候选特征生成的；产品匹配完全没有 reasoning 字段
- **后果**: 模型学不到真正的推理链，只会背模板；推理能力弱
- **修复**: 机构 reasoning 根据 target 和 candidate 的实际差异动态生成；产品输出加 reasoning 字段（如"核心名一致，剂型不同"）
- **文件**: `scripts/generate_data.py`
- **工作量**: 40 分钟

### P1-4: save_total_limit=2 太少
- **问题**: 只保留 2 个 checkpoint，中间一个损坏了就无法回滚
- **修复**: 改为 3 或 5
- **文件**: `scripts/train.py`
- **工作量**: 1 分钟

### P1-5: bf16 在 MPS 上的兼容性
- **问题**: Mac MPS 对 bf16 支持不完全，可能训练失败或精度异常
- **修复**: 检测平台，MPS 时用 fp32 或 fp16
- **文件**: `scripts/train.py`
- **工作量**: 10 分钟
