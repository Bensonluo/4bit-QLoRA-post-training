# GGUF 产物的独立同题评测

日期：2026-10-16 至 17。基线：`5fd78ae`。北极星的交接终点是模型与可信证据；转换和加载不能证明量化产物保持业务质量。本轮接通已有 GGUF 的实际开发对照，保持不做 serving 的边界。

## 实现

- 新 GGUF 导出附带 `hf_tokenizer/`，从实际转换的合并模型复制配置、分词文件和模板，不复制权重或 Python 代码；它们与 GGUF 一同进入内容回执。旧回执保持原样，缺少此目录的旧导出需导出到新目录。
- 固定官方 llama.cpp `436f6f89e1e581249900b37a5b8a12a36a6d0912` 的本地 CPU 桥使用 stdin/stdout JSON 行通信，加载一次模型，每题创建独立 context，四线程、纯 argmax、不附加聊天模板、不移位或截断输入，不启动服务器。Git checkout、桥源码、二进制、静态 CPU 构建设置和协议均可核验。
- `setup_gguf_tools.py` 实际构建、自检并输出运行器路径，`--check-only` 拒绝旧源码/改动二进制/缺失准备证据。无需安装新的 Python 包，不修改项目虚拟环境。
- `eval-compare --gguf-export-dir DIR --gguf-runtime PATH` 和页面显式按钮在同一报告中对照基座、本轮 HF、GGUF。页面从已选导出与已准备工具填写默认路径，保留手工覆盖。缺失或不匹配的交接证据会在加载 HF 前拒绝。
- GGUF 具有独立文件、运行器及 tokenizer 身份；训练来源单独记录，不冒充正在运行 HF adapter。生成前后复核来源与文件，改动不能留下有效成绩。诊断重新验证源训练回执；训练血缘有效不意味着业务质量有效。
- GGUF 仅用于开发对照，不绑定 HF 迭代采用决定，不支持最终验收身份冻结；最终验收入口明确拒绝，且不揭示或冻结留出题。导出回执中的 `not_run` 保留导出时事实，评分另存评测报告。

## 生成与报告契约

含 GGUF 的报告使用 `greedy_token_contract_v2`，旧 HF 报告保持 `greedy_v1`。新旧协议不能直接混比。新协议绑定实际提示、标准答案、完整输入 token、生成 token、EOS、停止原因、长度、HF 解码规则和 Transformers 版本。

原生分词结果必须逐 token 等于携带的 HF tokenizer；模型间同题输入 token 与 EOS 规则也必须相等。不一致题记失败，不作为可评分答案。指定的源 HF EOS 被保留在生成 token 中并停止；长度耗尽记截断，失败和截断保留全部题数分母。原生 token piece 仅供诊断，权威业务文本统一由 HF `decode(..., skip_special_tokens=True)` 产生，避免特殊 token 与不完整 UTF-8 的解码差异。

审计复现了 Transformers 5.9.0 的默认继承：传入 `GenerationConfig` 的空字段仍会从模型加载配置继承禁词、重复惩罚、强制 EOS。v2 在自己加载的 HF 模型上改用独立默认配置；实际小型 Llama 回归验证生成 token 与逐步无修饰 argmax 一致。否则仅检查“greedy”标签和输入 token 不能证明生成规则相同。

保存后读取报告及跨报告比较共享逐题 token 与指标核验，同时检查请求路径与实际记录的 GGUF/运行器/tokenizer 身份。报告自洽核验不读取大权重；诊断与再次运行执行本地来源完整性复核。响应和输入写入都有超时，异常只释放本次子进程，不能留下后台生成或部分成功答案。
