# SFT 答案、结束标记与校准消费一致性

日期：2026-10-17。基线：`555e46d`。本轮从 R146 三模型全部截断的原始证据出发，核实训练实际消费，并修复可确定的监督门禁和 LoRA-GA 校准缺陷。

## 为什么先查训练与提示

R146 的成功运行 `wb-cc351445b14041f58602c99c0c79fba4` 实际只有两条训练样本、两次优化步骤。训练答案全为“上涨”，固定开发题的两条答案全为“未上涨”。两条训练记录各有 152 个有效 token，因果位移后监督 151 个位置，其中答案 1 个、EOS 1 个；其余为输入与模板。原配置 `max_length=512` 完整保留答案与 EOS。

因此，这次微型工程试验不能证明模型已学会任务或停止规则。训练 loss 是全提示损失，不能把它当答案正确率。原始生成中既没有 tokenizer EOS，也没有模型配置中的另一个结束 token；本次未停止不能由“漏停第二 EOS”解释。

实际基座另做了受控诊断：保留同两道题的原始 Alpaca 文本，分别直接生成、把同样文字包为原生聊天模板的一条 user 消息、再显式关闭思考模式。其余仍为相同的 128 token 上限、贪心生成及 tokenizer EOS。六次输出全部触及上限：默认聊天模板出现思考内容，关闭思考后仍输出长解释。只换外层模板没有解决此例；这个实验也没有检验一套重新训练的原生聊天协议。

[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-1.7B) 给出了原生模板与思考开关，并提示思考模式下贪心解码可能重复。[Transformers 聊天模板文档](https://huggingface.co/docs/transformers/v5.9.0/en/chat_templating) 说明训练与生成的格式要求。这些是后续显式提示协议设计的依据，不是本次失败根因的证明。旧训练、评测与导出的提示协议保持原样。

## 已复现并修复的缺陷

1. **结束标记丢失仍能确认警告后训练。** 旧预检记录 `terminal_eos_supervised=False`，却只发截断警告。现在原始完整记录的 EOS 必须处于实际监督位置，否则阻断；右截断恰停在内部同 ID 的 EOS 也不能冒充原始末尾。真实 Qwen tokenizer 和同一历史数据快照在长度 155 时旧结果为警告，新结果阻断；长度 156、512 继续通过。该长度 155 例丢失的是留出分区末尾 EOS，没有重新生成或评分留出题。
2. **部分答案仍能确认警告后训练。** 已验证字符边界显示部分标准答案未进入监督时阻断，包括左截断丢掉答案开头，以及文字完整可见、首个答案 token 却被因果位移跳过的情况。新增 `answer_supervision_complete` 区分可见与实际监督。只有完整答案监督与原末尾 EOS 均保留时，上下文截断才继续交用户核对。慢 tokenizer 无法验证答案边界时仍如实标记未知；只有 EOS、没有有效因果上下文的记录不再能借左 padding 绕过。
3. **LoRA-GA 校准优化了不同的目标。** 原回调直接把 `input_ids` 当标签，padding 位置产生非零交叉熵梯度。修复后与正式训练共用 collator，真实 EOS 保留，padding 的损失屏蔽。校准先应用同一 `max_samples`、分区比例和随机种子，再从实际训练分区截取校准样本；不再提前截源数据导致使用验证行或超出训练样本上限。
4. **预检说明误报截断位置。** CLI 与页面共用的摘要区分答案丢失、EOS 丢失、上下文截断与边界未知；不再把所有“未发现答案丢失”都说成“只截掉输入”。

LoRA-GA 的既有梯度缓存没有模型、数据与学习目标的可核验绑定，PEFT 会直接加载它并跳过校准。因此现在提前拒绝已有缓存路径，包括空文件与符号链接，不删除或覆盖它们。`lora_ga_cache_file` 可设为新路径保存本轮梯度供检查，或设为 `None`；有来源验证的缓存复用尚未实现。PEFT 只接收同一文件系统内的私有新路径，完成后以硬链接原子发布；目标被并发占用时失败且保留外来文件，异常不发布临时缓存。这是高级 LoRA-GA 选项的兼容性变化，普通 LoRA 训练不受影响；不支持硬链接的文件系统不能使用可选缓存输出，可设为 `None`。

已有预备运行在启动时重新执行门禁，不能通过确认旧警告绕过。原始运行、数据版本、模型文件、评测报告均未改写。这些确定性缺陷是审计发现的独立问题，不能宣称它们解释或修复了 R146 的零分。
