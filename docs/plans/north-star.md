# TuneSmith 北极星目标(权威版本)

2026-09-27 定稿。本文取代此前散落在交接文档与讨论中的模糊表述,是产品一切优先级判断的最高依据。医疗实体、主数据、实体匹配等仓库内案例仅为演示素材,不属于本目标。

---

## 一句话定义

**让任意行业、任意业务场景中雇不起算法工程师的人,以可承担的成本、在自己的消费级硬件上,独立运转模型后训练的完整闭环——把原本需要一整套 ML 团队的工具链,压缩成一个非专家能安全操作、看得懂、可追溯的工位。**

## 服务对象

- **量级**:10 万量级的不同垂类行业与业务场景。这是长尾**分布**,不是若干个名单内的垂类;任何单案例的成败都不构成对北极星的证明。
- **画像**:会写代码但不是算法工程师的人;所在的小公司/团队有真实业务数据和微调需求,雇不起(或不需要)专职算法工程师。
- **硬件**:一张消费级显卡(8–24GB)或 Apple Silicon。分析 Agent 为 BYOK 可选项;没有任何 API 密钥的用户也能经基础路径走通。
- **反画像(诚实告知后送别)**:需要数据中心级训练、需要推理服务平台、或拿不出任何业务数据的人。

## 交付的完整闭环(产品边界内的全部环节)

1. **数据准备与版本(DVC 角色)**:任意原始业务表格/多源资料 → 组合、转换、受限增强 → 真实预览确认 → 版本化分区(内容摘要 + 行级血缘,可复现、可追溯)。
2. **训练方案制定**:基于数据事实、本地模型事实、本机硬件与真实 tokenizer 预检的方案——Agent 推荐或确定性基础方案,高级用户可手工覆盖。
3. **启动训练**:确定性预检门禁(截断/答案保留/EOS 契约)→ 单卡训练 → 有限且显式的技术恢复。一次授权可自动执行到对照完成。
4. **训练后指标**:训练指标 + 业务对照指标(同题、同协议、基座/父轮/本轮三模型)。
5. **可视化**:面向非专家的呈现——实时曲线、对照表、逐条坏例、诊断提示(指令回声、截断、泄漏),让用户"看得懂发生了什么"。
6. **试验管理**:实验记录、迭代轮次(父子轮、固定题集、改进假设与决策留痕)。
7. **模型管理**:注册、血缘(模型 ↔ 实验 ↔ 数据版本互相反查)、champion/challenger。
8. **迭代改进**:坏例 → 改进假设 → 修订数据/配置 → 自动执行 → 三模型对照 → 用户决策(采用/继续/停止/证据不足)。
9. **(交接)** 合并导出为可被 vLLM/Ollama/LM Studio 直接加载的模型,附完整证据链。

## 硬边界

- **不做推理/serving 层**:终点产物是"模型 + 证据",部署交给成熟的推理生态。
- **不做多卡产品主线**:单卡是承诺;分布式能力留作 CLI 逃生舱。
- **不替用户宣判业务成败**:产品验证安全、呈现证据、支持判断;业务判断权与最终验收永远在用户手里。
- **不为单个垂类做模板化开发**:通用机制是产品,领域案例只是素材。
- **密钥纪律**:BYOK;密钥只走环境/会话,永不写入文件、日志或对话。

## 核心难点与安全层

**难点**:每个场景都存在几处"答案只在业务方头脑里、数据本身推不出来"的语义判断(标签是不是对的监督信号、数据够不够、什么输出算正确)。这些判断只能交给不可靠的 LLM 和不懂 ML 的用户,中间没有专家仲裁——**判断错一处,后续工程全部白做,且错误会无声通过**。

**安全层**(通用机制,与任务类型无关,是产品区别于一切微调工具的所在):

- **盲标核验**:抽 K 条隐藏现有答案,用户自己作答,比对一致性——验证监督信号的业务自洽性,零 GPU 成本,不通过则训练不开始。
- **对比预览**:给两个解释让用户选,而不是给一个让他点头;错误在对比中藏不住。
- **可学性探针**:全量训练前用最少算力探测"这份数据学不学得出这个任务",学不出就直说。
- **同题对照**:任何模型主张都必须来自同题集、同协议的对照,单次训练的分数不作为比较依据。
- **确定性门禁**:凡是结构上可验证的(泄漏、格式、截断、重复、血缘),全部用代码验证,不依赖 LLM 或用户自觉。

**编码原则**:每一次性专家判断,要么被编码进产品(服务全部 10 万场景),要么被转化为用户做得起的核验动作;两者都做不到的,诚实拒绝并说明。

## 度量体系

- **北极星指标**:任意抽取真实场景,一个非专家独立走完闭环且语义判断不出错的概率(**覆盖率 × 独立通过率**)。
- **过程漏斗**:上传 → 分析 → 预览确认 → 全量验证 → 分区 → 预检 → 训练 → 对照 → 决策;每段的通过率与专家介入点计数,介入点清单就是下一轮开发的输入。
- **成本可计算**:每次运行如实给出耗时、硬件、电费,以及"对比调用 API 完成同等业务量"的账——"可承担的成本"必须是算得出来的数字。
- **诚实红线**:管道通过 ≠ 业务达标;零分如实记录;证据不足是合法结论;不以运行成功、loss 下降或样例通过宣称业务效果。

## 演进原则

- **分布驱动,不便利驱动**:场景多样性用场景矩阵系统性覆盖,真实外部用户做校准;仓库内现成案例只能当演示与回归,不能当北极星证据。
- **判断编码飞轮**:每撞见一种新的语义陷阱,就把它固化成门禁、诊断或 Agent 提问——产品速度的本质是"遇陷阱频率 × 编码成本",不是堆新功能。
- **架构是手段**:任何技术决策必须能回答"它让闭环中哪个环节的判断更安全、更便宜、或更看得懂";回答不了的,不做。

## 与现状的对照(2026-09-28 修订)

2026-09-27 定稿时的三处差距已全部收口,证据为恢复循环第 51-55 轮(提交 f24cfbd..3aa6eef,全量回归 1839 项全绿):**①按旅程串联**——环节⑨交接出口落地(train-export 合并导出 + 页面只读盘点),九环节在页面与 CLI 均有入口;**②非专家视角的可视化**——loss 曲线(含训练中实时)与趋势人话、对照表、逐条坏例、诊断提示(指令回声/截断/泄漏/输出坍缩)双侧同源同词汇;**③模型-实验-数据三角血缘**——服务层正反两向自 M3 起在位,第 51 轮起 CLI 与页面人话平权;度量体系的**过程漏斗**同批落地(funnel-report 停点快照)。

当前仍然真实开放的差距(按优先级):

1. **北极星指标从未被测过**:"覆盖率 × 独立通过率"需要真实外部非专家用户;试用模板(user-trial-log.md)就绪但未回收,现有全部验证——含场景矩阵 47 项 as_expected——都是开发者自测,按演进原则不构成北极星证据。
2. **Agent 判断的真实性证据不足**:自定义评分规则的真实 GLM 起草未成功验证;单次在线验证入口就绪但未尝试(密钥纪律,不盲试);业务理解准确性仅在虚构试点上检验过。
3. **Agent 全流程协作架构未设计**:从任务规约到多轮适配的整体架构文档(task-spec-and-agent-adaptation-design.md)尚未产出——单点能力齐备,协作方式仍是一轮一议。
4. **成本可计算的 CLI 平权缺口**:训练成本账(时长/功耗电价/API 对比口径)只在页面呈现,CLI 侧零入口。
